# 약관 → 레퍼런스 생성 파이프라인

분할된 약관 PDF에서 특약별 고유 내용만 뽑아 Q&A용 레퍼런스 md 5부를 만든다.

## 준비

```bash
pip install pymupdf
```

`pypdf`는 이 환경에서 cryptography 바인딩 오류로 import가 실패했다. PyMuPDF를 쓸 것.

## 실행

```bash
# 1단계: PDF 25개 → 텍스트 (work/f01.txt … f25.txt)
python3 extract_pdfs.py ~/약관PDF폴더 work

# 2단계: 텍스트 → 구조화 JSON (work/*.json)
python3 parse.py work

# 3단계: JSON → 레퍼런스 md 5부
python3 generate.py work 약관레퍼런스
```

PDF 파일명은 `…-1.pdf` ~ `…-25.pdf` 처럼 끝에 분할번호가 있어야 한다(`f01.txt` 매핑에 쓰인다).
`f01`은 주계약 + 상품목차, `f02`~`f25`가 특약 본문이다.

## 파일 역할

| 파일 | 역할 |
|---|---|
| `extract_pdfs.py` | PDF → 텍스트. PyMuPDF로 전량 추출 |
| `parse.py` | 목차 파싱 → 특약별 구간 분할 → 조항 분해 → 계열 분류 → 용어사전 |
| `clause_text.py` | 조항 본문 정제 공용 모듈 (2·3단계가 함께 씀) |
| `generate.py` | 레퍼런스 md 5부 출력 |

## 이 코드가 우회하고 있는 함정 3가지

고쳐 놓은 것이므로 **건드릴 때 주의**할 것.

### 1. Google Drive의 PDF 텍스트 추출은 파일당 약 20%를 잘라먹는다

99쪽 중 80쪽만 나온다. 쪽번호를 대조해서 발견했다 — 파일 사이에 19쪽씩 구멍이 났고,
거기 있던 특약 39개가 통째로 사라졌다. **반드시 원본 PDF를 직접 파싱할 것.**

### 2. 조항 본문 속 상호참조를 조항 제목으로 오인하면 본문이 잘린다

`제2-1조의8 [특약의 보장개시일]` 같은 참조가 문장 중간에 나온다.
조항 헤더 정규식은 **반드시 줄머리 앵커(`(?m)^[ \t]*`)** 를 붙일 것.
없으면 조항이 중간에서 끊긴다(발견 당시 약 1.2만 자 손실).

### 3. 목차 레이아웃이 추출 방식에 따라 다르다

PDF 직접 추출본은 특약명과 쪽번호가 **다른 줄**에 온다.
`read_toc()`가 두 형태를 모두 처리한다.

## 정제가 걷어내는 잡음

PDF 텍스트에는 아래가 문장 중간에 섞여 들어온다. `clause_text.clean()`이 처리한다.

- 단독 줄로 끼어드는 쪽번호
- 줄바꿈으로 쪼개진 단어 (한글은 하이픈이 없어 그냥 붙음) — 단, 다음 줄이 `1.` `①` `-` 등
  항목 머리면 붙이지 않는다(안 그러면 호 번호가 앞 문장에 달라붙는다)
- 면책기간 도해의 텍스트 파편 (`계약일[부활(효력회복)일]`, `2021년 4월 10일 2022년 4월 10일` 등)
- `설명 <…예시>` 박스가 문장 한가운데 통째로 끼어드는 것

## 산출물을 바꾸고 싶을 때

- **특약별 항목 구성** → `generate.py` 의 `01 지급사유` 블록
- **제2-3조에서 뽑을 조항 기준** → `clause_text.KEEP` / `clause_text.DROP` 정규식
- **계열 분류** → `parse.py` 의 `family()`
- **용어사전 병합 강도** → `parse.py` 의 `canon()` (마스킹을 늘리면 변형이 더 합쳐진다)
